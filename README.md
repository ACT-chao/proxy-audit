# proxy-audit

**从你本机正在运行的代理配置出发，端到端验证这条代理链路是否干净、可信。**

市面上检测代理的工具，大多站在"查一个陌生 IP"的立场。proxy-audit 的起点不同——它会**读取你本机 v2rayN / sing-box / xray / Clash 的实际配置**，看有没有被投毒，再做真实的传输层验证。这是它区别于其他工具的核心。

零依赖，纯 Python 标准库，单文件，跨平台。

---

## 为什么需要它

代理链路的风险不在"能不能用"，而在三个层面：

| 层面 | 典型风险 | 常规工具的盲区 |
|------|---------|--------------|
| **配置层** | 配置里被塞入隐藏转发出口，把银行/支付流量导向攻击者服务器 | 没人读你的本地配置 |
| **传输层** | 代理做 TLS 中间人解密（MITM）、注入 `X-Forwarded-For` 泄漏真实 IP、篡改内容 | 只测浏览器，命令行场景测不了 |
| **出口层** | 出口 IP 被标记为恶意、共享出口被别人搞脏 | 只给一个标签，不结合配置判断 |

proxy-audit 把这三层打通。

---

## 三层检测

### 第 1 层 · 配置层
读取本机代理客户端配置，静态审计：

- **出站投毒检测** — 检查 `outbounds` 里是否存在除主代理外的**额外出站连接**（隐藏转发是投毒的最常见手法）
- **入站暴露面** — 监听地址是否为 `0.0.0.0`（局域网/公网可借用）
- **DNS 劫持** — DNS 服务器是否为明文（可被旁路监听）、有无可疑 DoH 白名单
- **路由规则审计** — 是否存在把 `geoip:cn` / `geosite:private` 导向代理出口的异常规则
- **上游节点画像** — 协议、传输方式、加密级别（如 REALITY / TLS）

支持：v2rayN（xray/sing-box 内核）、Clash / mihomo / Clash Verge。

### 第 2 层 · 传输层
通过代理发起真实请求，主动验证：

- **中间人检测（MITM）** — 严格校验 TLS 证书链。若代理解密流量，证书链会断裂
- **证书签发者核查** — 读真实证书 issuer，排查自签 / 可疑 CA
- **请求头注入** — 检测 `X-Forwarded-For`、`Via`、`X-Real-IP` 等暴露真实身份的注入头
- **内容篡改** — 校验明文 HTTP 响应结构是否被污染
- **出口 IP 稳定性** — 多次采样，识别轮换/共享出口

### 第 3 层 · 出口层
- **IP 信誉画像** — 是否被标记为代理/VPN、机房/住宅/移动网络类型
- **地理位置与运营方** — 出口实际归属
- **分流验证** — 国内站点是否正常直连（防误绕）

## 安装与使用

无需安装，只需 Python 3.8+。

```bash
# 自动探测代理并体检
python proxy_audit.py

# 指定代理
python proxy_audit.py --proxy 127.0.0.1:10808

# 额外输出 JSON 报告
python proxy_audit.py --json report.json

# 关闭彩色输出（便于重定向到文件）
python proxy_audit.py --no-color
```

退出码：`0` = 干净/需注意，`2` = 发现高风险问题（便于接入 CI 或监控）。

## 局限与边界

诚实说明这个工具**做不到**什么：

- **不检测服务端行为**。配置干净 ≠ 服务端在服务端做坏事。它能验证"传输没被篡改"，但无法证明"服务方不记录日志"。
- **DNS 泄漏检测不完整**。浏览器有独立的 DNS 解析路径，命令行工具测不到。建议配合 [dnsleaktest.com](https://dnsleaktest.com) 交叉验证。
- **不做节点存活监控**。它是一次性体检，不是守护进程。
- **IP 信誉依赖第三方 API**（ipinfo.io / ip-api.com），结果受这些服务的数据质量影响。
